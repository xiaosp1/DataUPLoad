## W-FLASH-01 实时页闪烁根治（DONE 21:1x）

### 根因（2 个）
1. **后端**：`ScreenServiceImpl.buildScreenData()` 排序行 `Comparator.comparingInt(Line::getOrder)` 拆箱 null → NPE。
   - `Line.order` 字段带 `@TableField(exist = false)`，MyBatis-Plus 从不装载，恒为 null。
   - sendScreen 每 5s 抛一次 NPE → WS screen 通道从未成功推数据（8/1 backup 日志 12985 次 0 成功）。
2. **前端**：`OccupancyPanoramaBar` 独立 `setInterval(5s)` 与 WS 不同源 + `watch deep` → 重绘闪烁。

### 修复
- **后端**：`ScreenServiceImpl` 排序改 null-safe（`getOrder()==null ? MAX_VALUE : getOrder()` + `Color nullsLast naturalOrder`）；`GlobalTaskManager.sendScreen` catch 保留 `log.warn(msg, ex)` 含堆栈。
- **前端**（方案 A 统一 WS 单一刷新源）：
  - `stores/screen.ts`：WS 单例快照 `screenState.snapshot.lines[]`（5s 服务端广播）。

1. **`chartInitedFlag is not defined`**：初版用模块顶层 `let`/`ref`，esbuild + vite SFC 编译后变量声明丢失（`const chartInitedFlag = (window as any).__rtChartInited ?? ### ⚠️ 当前现场（P0 待老板拍板）

### 根本原因（DB 实测铁证，非猜测）
**`DefectRecordServiceImpl.handleDetectData()` 的 `@Transactional(rollbackFor=Exception.class)` 把超长事务挂在连接上。**
- 38 条产线每 5s 各 POST /client/data/detect 一次
- 单次请求事务内 = 4 张表几十条 SQL：`getByLineNoAndFaceNo` + `addDefectTypeIfNotExist`（line_defect_type upsert）+ `selectList`/循环 insert+update `defect_day_record` + `selectOne`×2 + insert/update `line_day_record` + `updateById line`
- 并发一高 → 事务互相锁等待（`transactionid` Lock）+ `idle in transaction`（SQL 做完但事务不提交）→ **持有连接不还** → Hikari 50 连接被占满 → sendScreen/login 拿不到连接 → WS 推不出 → **页面无数据**
- 重启后 30 分钟实测：55 连接全被占，25 idle in transaction + 25 active 全锁等待，事务 age 9 分钟~40 秒
- **验证索引无效**：已加 5 个索引（见下）仍锁死 → 证明瓶颈是**事务粒度太大**，不是索引

### 已执行的 DB 层修复（有效但不够）
- **kill 卡死锁事务**：`SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE xact_start IS NOT NULL...`（临时恢复，反复复发）
- **已建索引**（P:\psql via PG14）：
  - `uq_line_defect_type_line_face_name`（UNIQUE on line_no, face_no, name）
  - `ix_defect_day_record_lf`（line_no, face_no, type）
  - `ix_defect_day_record_tlf`（time, line_no, face_no）
  - `ix_line_day_record_tlf`（time, line_no, face_no）
  - `ix_status_record_lnf`（line_no, face_no, update_time）
  - `ix_status_record_ut`（update_time）
