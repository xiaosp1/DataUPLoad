### 今日三大修复（全部实证）
1. **MES 拉配方 `GET /client/plan`** → success ✅
   - 根因：`WhiteListUtil.IPLIST` 白名单未自动加载 → `/client/**` 全被 client_token 掐死
   - 修复：调 PSM 自带 `/white-list/refresh` 端点重载白名单（white_ip 表有 127.0.0.1 + *.*.*.*）
   - `data:[]` 正常——`plan_to_line` 表空（还没绑配方）
2. **报警上传 `POST /client/data/alarm`** → success ✅
   - 根因：`AlarmRecordServiceImpl.add()` 里 `ReUtil.get(template, message)` 正则匹配失败返回 null → 下一行 `message.contains(name)` NPE → 10500
   - 修复：434 行 `ReUtil.get` 后加 null 兜底（`if (message == null) message = form.getMessage()`）
3. **产线实时上报 `POST /client/data/detect`** → 全面恢复 ✅
   - 根因 A：连接池 50 连接被 38 线并发写满（jstack 实证 322 线程卡 getConnection、50 BLOCKED）→ 按 100 条产线扩容 `maximum-pool-size: 200 / minimum-idle: 40 / connection-timeout: 30000`
   - 根因 B：`line_day_record` 存在 101 行重复（同 time+line_no+face_no）→ `selectOne()` 抛 TooManyResultsException → 10500
   - 修复：清 101 行重复（每组保留 max id）+ `DefectRecordServiceImpl` 171/192 行 `selectOne` 加 `LIMIT 1` 防抖
   - 验证：重启后 2 分钟 detect ok 453 条 / 10500 0 条

### 报警推送根治（W-ALARM-PUSH）— 今日收官
- **根因（WS uid 广播错位）**：
  - 前端报警 WS 一律 `uid = userStore.id ? String(userStore.id) : 'web'`，登录后 uid=用户id(1)，type=alarm
  - 后端 `sendAlarmTextMessage()` / `sendAlarmSoundWsMessage()` 用 `broadcastByUid(json, "web")` → 只推给 uid="web" 的 session
  - 登录态 uid=1 ≠ web → 永远收不到；只有未登录/登出（uid 回 web）才能收到
- **WS 实测实证**：连 uid=1 vs uid=web 两个 alarm WS —— uid=web 收到 alarm+sound 2 条，uid=1 0 条
- **修复**：`AlarmRecordServiceImpl` 两处 `broadcastByUid(…,"web")` → `broadcastByType(…,"alarm")`（按 type 广播，登录态用户也能收到；与 `AlarmWebSocketHandler.push()` 现用法一致）
- **修复后 WS 实测**：uid=1 收到 alarm+sound 3 条，POST /client/data/alarm → success ✅
