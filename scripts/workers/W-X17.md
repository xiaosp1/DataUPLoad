# W-X17：灰盒验证 3 - alarmCount 聚合真触发

**优先级**：P0（灰盒跑法第 3 关：验证 PSM alarmCount 合并推送而非逐条推送）
**金标准**：PSM 反编译 `YKServiceImpl.pushAlarm2YK` 第 140-141 行（详见 W-F03 派工单）
**依赖**：W-X11（必须先部署）
**预计**：20 分钟

---

## 背景

PSM `alarmCount` 聚合 = 同 `(lineNo + faceNo + defectName + alarmTime 同一分钟)` 的多条报警**合并成 1 条 push alarm**，count 字段累加。
W-F03 在 hik-java 端补齐了：`YKServiceImpl.pushAlarm2YK` 第 140-141 行的聚合判断 + count 累加。

但**没真测过**：连推 10 条同 alarm → 看 PG alarm_record 是 10 条独立还是聚合（alarm_record 应该 10 条，但 yk push 应该是 1 条合并）。

## 必须做的事（5 步法）

### Step 1：基线快照
- 查 alarm_record 总数 + 当前 minute 的 TEST_LINE_X17 行数：
  ```sql
  SELECT COUNT(*) FROM alarm_record;
  SELECT COUNT(*) FROM alarm_record WHERE line_no = 'TEST_LINE_X17';
  ```
- 记到报告

### Step 2：连推 10 条同 alarm（必须在同一分钟内）
- 用循环 POST `http://127.0.0.1/client/data/alarm`：
  ```powershell
  for ($i=1; $i -le 10; $i++) {
      $body = @{
          lineNo = "TEST_LINE_X17"
          faceNo = "TEST_FACE_X17"
          defectName = "测试缺陷_alarmCount聚合验证"
          type = "DEFECT"
          count = 1
          level = "警告"
          message = "W-X17 alarmCount 测试 $i/10"
      } | ConvertTo-Json
      Invoke-WebRequest -Uri "http://127.0.0.1/client/data/alarm" -Method POST -Body $body -ContentType "application/json"
      Start-Sleep -Milliseconds 100
  }
  ```
- **关键**：10 条必须都在同一分钟内（PSM 聚合粒度 = alarmTime 同一分钟）

### Step 3：等 10 秒 + 查 PG 验证
- 等 10 秒（让异步处理跑完）
- 查 alarm_record：
  ```sql
  SELECT uuid, line_no, face_no, defect_name, count, solve, create_time
  FROM alarm_record
  WHERE line_no = 'TEST_LINE_X17'
  ORDER BY create_time ASC;
  ```
- **期望结果**（PSM 同款）：
  - alarm_record 入库 **10 条**（每条对应一次推送）
  - 但 yk push 应该只 **1 条合并**（AlarmDTO.count = 10）
- **yk 日志验证**：找 `pushAlarm2YK` 关键字 + count 字段
  ```
  pushAlarm2YK called: count=10, defectName=测试缺陷_alarmCount聚合验证, lineNo=TEST_LINE_X17
  ```
  或者 `merge 10 alarms into 1 push` 类似日志

### Step 4：yk 没真推验证（enable=false 生效）
- yk 推送记录：0 条
- 日志关键字：
  - ❌ 找不到：`get ticket success`
  - ✅ 找得到：`push alarm to yk error, ticket is null` 或 `yk.enable=false skip push`
- 这是验证 enable=false 熔断仍然有效（即使 alarmCount 聚合了，也卡在最后一公里）

### Step 5：清理测试数据（必须）
- 删：
  ```sql
  DELETE FROM alarm_record WHERE line_no = 'TEST_LINE_X17';
  ```
- 复查：
  ```sql
  SELECT COUNT(*) FROM alarm_record; -- 回到基线
  SELECT COUNT(*) FROM alarm_record WHERE line_no = 'TEST_LINE_X17'; -- 0
  ```
