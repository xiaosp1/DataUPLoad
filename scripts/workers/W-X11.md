## 必须做的事（按顺序）

### 1. 打 merged.jar（带 W-F01-F05 + W-X01B 全部新功能）
- 入口：`E:\DEMO\数据采集\logs\rebuild-full.ps1`（参考 W-B03 落档）
- 步骤：
  1. `cd DataupLoad && mvn clean package -DskipTests`（确保所有 module 进 fat-jar）
  2. 解压 fat-jar 到临时目录
  3. 把 `BOOT-INF/lib/*.jar` 全部 copy 进来（除 framework-starter）
  4. `jar c0fMf` 重建（**c0 = STORED 模式，M = 不带 manifest**）—— 嵌套 jar 必须 STORED，否则 spring-boot JarLauncher 读不出
  5. 改用 `jar umf` 加 manifest
- 输出：`E:\DataupLoad-final.jar`（目标 ~108 MB）
- 验证：jar 内必须包含以下 .class（用 `jar tf` 验）：
  - `com/hikrobotics/solution/module/alarm/entity/IgnoreAlarm.class`
  - `com/hikrobotics/solution/module/alarm/service/impl/IgnoreAlarmServiceImpl.class`
  - `com/hikrobotics/solution/module/alarm/web/IgnoreAlarmController.class`
  - `com/hikrobotics/solution/module/alarm/task/AlarmRetentionTask.class`
  - `com/hikrobotics/solution/module/alarm/task/IgnoreExpireTask.class`
  - `com/hikrobotics/solution/module/alarm/service/ClientOnlineChecker.class`
  - `com/hikrobotics/solution/framework/security/WhiteListScheduledRunner.class`
  - `com/hikrobotics/solution/module/yingke/service/impl/YKServiceImpl.class`（W-X01B 重写版，必须含 ThreadPoolTaskScheduler）

### 2. Flyway baseline 升级 1.19 → 1.20
- 改 `DataupLoad/config/application-prod.yml`：
  - `spring.flyway.baseline-version: 0` → `1.20`（保留 baselineOnMigrate=true）
- 或更安全：在 `application.yml` 加 `spring.flyway.baseline-version: 1.20` 让 Flyway 把 1.20 当 baseline，已经存在的 V1.0-V1.19 不重跑，V1.20__ignore_alarm.sql 真执行
- **不要改 `baselineOnMigrate: true`**（已经在用，改了会破坏已有 schema）

### 3. 重启 hik-java
- 杀当前 PID 15868（`Stop-Process -Id 15868 -Force`）
- 启 merged.jar：
  ```powershell
  java -jar -Dfile.encoding=UTF-8 E:\DataupLoad-final.jar `
       --spring.config.location=classpath:/,file:E:/DEMO/数据采集/DataupLoad/config/
  ```
- 后台启动（`Start-Process` + RedirectStandardOutput）

### 4. 验证 V1.20 SQL 真生效（4 重）
- 4.1 **Flyway 历史**：查 `flyway_schema_history` 表，最后一条必须是 `1.20 | ignore_alarm | SUCCESS`
  ```sql
  SELECT version, description, success FROM flyway_schema_history ORDER BY installed_rank DESC LIMIT 3;
  ```
- 4.2 **ignore_alarm 表存在**：
  ```sql
  SELECT table_name FROM information_schema.tables WHERE table_name = 'ignore_alarm';
  ```
  → 必须返回 1 行
- 4.3 **白名单定时任务跑起来**：日志必须有 `white ip list refresh over, count=N`
- 4.4 **yk ticket 没拉**（验证 enable=false 生效）：日志必须是 `push alarm to yk error, ticket is null` 或直接看不到 `get ticket` 字样
- 4.5 **端口 80 监听**：netstat 看 80 端口在听
- 4.6 **报警落 PG 正常**：连推 1 条 → PG `alarm_record` +1

## 失败处理

- merged.jar 打不出 → 检查 mvn log，常见是嵌套 jar 没 STORED（用 jar c0fMf）
- V1.20 SQL 执行失败 → 看 Flyway 错误日志，常见是已有同名表或字段冲突
- 重启后 80 端口没起 → 看 error.log，常见是 bean 注入失败
- 任何失败立刻群里报，不静默
