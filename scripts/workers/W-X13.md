# W-X13：EdgeHost（C# 端）补 yk.enable 开关 - PSM 同款

**优先级**：P1（EdgeHost 兜底：将来切回 EdgeHost 不重蹈 7/21 16:03 覆辙）
**金标准**：PSM `@ConditionalOnProperty(prefix="yk", name="enable")` 1:1
**依赖**：无（独立工单，可并行）
**预计**：45 分钟

---

## 背景

7/21 16:03 EdgeHost 一启动就推 1328 条报警到 MES / 飞书群被打爆，老板 16:08 紧急叫停。
根因之一：EdgeHost（C# 端）**没有 yk.enable 开关**，修完字段一启动就自动推。

hik-java 端 W-X01B 已经加了 enable 开关（PSM 同款 @ConditionalOnProperty），但 EdgeHost 端到现在都没补。
将来切回 EdgeHost 时会再次踩坑，所以本工单把开关补上。

## 必须做的事

### 1. 找现有 yk 配置类
- 路径候选：
  - `src/IntcoEdge.EdgeHost/Configuration/YingkeGatewayOptions.cs`
  - `src/IntcoEdge.EdgeHost/Configuration/YkOptions.cs`
  - `src/IntcoEdge.EdgeHost/appsettings.json`（看 `YingkeGateway` 段）
- 用 `grep -r "WorkshopCode" src/IntcoEdge.EdgeHost/` 找（PSM ykConfig.workshop 在 .NET 端叫 WorkshopCode）

### 2. 加 Enable 字段
- 在 Options 类里加：
  ```csharp
  public class YingkeGatewayOptions
  {
      public bool Enable { get; set; } = false;  // 默认 false，铁则 36
      public string WorkshopCode { get; set; } = "QZN2";
      // ... 现有字段
  }
  ```
- `appsettings.json` 加：
  ```json
  "YingkeGateway": {
      "Enable": false,
      "WorkshopCode": "QZN2",
      ...
  }
  ```

### 3. 加熔断点（PSM `@ConditionalOnProperty` 同款）
- 在 `YingkeServiceImpl` (C# 端) / `IntcoHttpClient.PushAlarmAsync` / `DetectController.DispatchAlarmsAsync` 三处加：
  ```csharp
  if (!_ykOptions.Enable)
  {
      _logger.LogInformation("yk.enable=false skip push alarm (uuid={Uuid})", alarm.Uuid);
      return;  // 不抛异常，不重试
  }
  ```
- **加 3 处是为了兜底**：哪怕将来某处忘了判断，最起码有 2 道防线

### 4. 写测试（铁则 19/20 强化）
- 新增测试文件：`src/IntcoEdge.Tests/Service/YkEnableOptionTests.cs`
- 测试用例：
  - `EnableFalse_PushAlarm_DoesNotCallYkApi`（断言 httpclient.SendAsync 没被调用）
  - `EnableTrue_PushAlarm_CallsYkApi`（正常路径）
  - `EnableFalse_DefaultConfig_LoadedAsFalse`（验证默认值）
- 用 `Mock<HttpMessageHandler>` 拦截 HTTP 调用

### 5. 落档 ADR
- 新增 `docs/adr/0006-yk-enable-circuit-breaker.md`：
  - 背景：7/21 16:03 报警风暴 + 老板 21:54 灰盒跑法
  - 决策：yk.enable 默认 false，熔断点 3 道
  - 影响：EdgeHost / hik-java / 灰盒 SOP 全部对齐
  - 状态：Accepted
