# W-X15：灰盒验证 1 - 同化逻辑（assimilation）真触发

**优先级**：P0（灰盒跑法第 1 关：验证 PSM 同化逻辑 1:1 生效）
**金标准**：PSM 反编译 `AlarmRecordServiceImpl.add()` 同化路径（详见 W-A18 报告 3.5 节）
**依赖**：W-X11（必须先部署）
**预计**：20 分钟

---

## 背景

PSM 同化逻辑（assimilation）= 同 `(defectName + lineNo + faceNo + type)` 的旧 UNSOLVED 全部改成 IGNORE，新插一条 UNSOLVED。
这是 PSM 7/21 16:03 我们被刷屏 1328 条/2 分钟的根因之一 —— 我们没有这个同化逻辑。
W-A18 在 .NET 端移植了，hik-java 端 W-F01-F05 + V1.20 SQL 也补齐了，但**没真测过**。

## 必须做的事（4 步法）

### Step 1：基线快照
- 查 PG 当前 alarm_record 总数：
  ```sql
  SELECT COUNT(*) FROM alarm_record;
  SELECT COUNT(*) FROM alarm_record WHERE solve = 2; -- UNSOLVED
  SELECT COUNT(*) FROM alarm_record WHERE solve = 3; -- IGNORE
  ```
- 记到报告：deploy 后基线

### Step 2：构造测试数据（手动推 6 条）
- 用 `curl` / `Invoke-WebRequest` POST 到 `http://127.0.0.1/client/data/alarm`，body 走 PSM 同款 AlarmInputForm 格式：
  ```json
  {
    "lineNo": "TEST_LINE_X15",
    "faceNo": "TEST_FACE_X15",
    "defectName": "测试缺陷_同化验证",
    "type": "DEFECT",
    "count": 1,
    "level": "警告",
    "message": "W-X15 同化测试 1/6"
  }
  ```
- **必须 POST 6 条**：5 条同 `(defectName, lineNo, faceNo, type)`，第 6 条不同 lineNo
- **重要**：用 TEST_LINE_X15 / TEST_FACE_X15 这种**测试名**，因为现在 hik-java 没启 PSM 命名白名单（W-A13 在 EdgeHost 端有，hik-java 没移植）—— 这就是为什么本工单用测试名

### Step 3：等 5 秒 + 查 PG 验证同化
- 等 5 秒（处理异步）
- 查 PG：
  ```sql
  SELECT uuid, line_no, face_no, defect_name, solve, create_time
  FROM alarm_record
  WHERE line_no = 'TEST_LINE_X15'
  ORDER BY create_time ASC;
  ```
- **期望结果**：
  - 5 条同 (lineNo, faceNo, defectName, type) 的 → **前 4 条 solve=3 (IGNORE)** + **第 5 条 solve=2 (UNSOLVED)**
  - 1 条不同 lineNo 的 → solve=2 (UNSOLVED)
- **总新增**：6 条 alarm_record
- **总 UNSOLVED**：2 条（第 5 条 + 不同 lineNo 那条）
- **总 IGNORE**：4 条（前 4 条被同化）

### Step 4：清理测试数据（必须）
- 删：
  ```sql
  DELETE FROM alarm_record WHERE line_no = 'TEST_LINE_X15';
  ```
- 复查 `SELECT COUNT(*) FROM alarm_record;` = 基线数
