## 3. 额外发现（critical findings）

### 3.1 Bug #1：`IgnoreAlarmServiceImpl.isIgnore()` 抛 BadSqlGrammarException（**最严重**）

**复现命令**：
```powershell
# 任一发一条有效报警（isInterestingDefect=true）就会触发
Invoke-RestMethod -Uri http://127.0.0.1:80/client/data/alarm -Method Post `
  -Body '{"uuid":"isignore-test","lineNo":"L","faceNo":"F","type":1,"level":1,"message":"[bad] alarm"}' `
  -ContentType "application/json;charset=UTF-8"
```

**响应**：`{"success":false,"code":10500,"message":"操作异常"}`

**DataupLoad.log 节选**：
```
ERROR [GlobalExceptionHandler.defaultExceptionHandler:105] [Unknown Exception]
### Error querying database.  Cause: org.postgresql.util.PSQLException:
   错误: 操作符不存在: character varying > timestamp without time zone
### The error occurred while setting parameters
### SQL: SELECT COUNT(*) AS total FROM ignore_alarm
        WHERE (type = ? AND defect_name = ? AND line_no = ? AND face_no = ?
               AND end_time > ?)
### Cause: org.postgresql.util.PSQLException: 错误: 操作符不存在
   : character varying > timestamp without time zone
   ...
   at com.hikrobotics.solution.module.alarm.service.impl.IgnoreAlarmServiceImpl
      .isIgnore(IgnoreAlarmServiceImpl.java:42)
```

**根因**：
- `ignore_alarm.end_time` 是 `varchar(19)`（V1.20 schema）
- `IgnoreAlarm.endTime` 字段类型是 `LocalDateTime`
- `IgnoreAlarmServiceImpl.isIgnore()` 用 MyBatis-Plus `LambdaQueryWrapper.gt(IgnoreAlarm::getEndTime, LocalDateTime.now())` 比较
- PG 拒绝 `varchar > timestamp` 的隐式类型转换 → 抛 `BadSqlGrammarException`

**影响**：
1. 每次有效报警都抛异常（污染日志、性能损耗）
2. HTTP 响应统一是 `操作异常`（误导前端/集成方）
3. sendAlarmMessage 在 `isIgnore()` 异常时整体中断 → yk 不推 + WS 不发（但这是**假象** —— 白名单逻辑并没生效，只是异常短路）
4. AlarmRecordServiceImpl.add() 没有 @Transactional → save/update 已 commit，异常不影响 PG；但语义上是 500 错误

**修复建议**（供 PM 派工单 W-X22）：
```sql
-- 方案 A（最小改动）：改 schema
ALTER TABLE ignore_alarm ALTER COLUMN end_time TYPE timestamp 
  USING to_timestamp(end_time, 'YYYY-MM-DD HH24:MI:SS');
-- 已有数据可保留（如 2099-12-31 23:59:59 → 2099-12-31 23:59:59+08）

-- 方案 B（不改 schema）：改 SQL
-- 在 IgnoreAlarmMapper.xml / IgnoreAlarmServiceImpl 加 CAST：
SELECT COUNT(*) FROM ignore_alarm
WHERE ... AND CAST(end_time AS timestamp) > #{now}
-- 同时调整 IgnoreAlarm.endTime 字段类型为 String（或继续 LocalDateTime 但自定义 TypeHandler）
```

**优先级**：🔴 **高** — 影响所有有效报警的 HTTP 响应语义，且隐藏了白名单逻辑真实状态。老板上线 MES 前必须修。

```java
public BaseResult handleAlarmIgnore(IgnoreAlarmDTO form) {

    BeanUtils.copyProperties(form, entity);
    entity.setStartTime(form.getStartTime());
    entity.setEndTime(form.getEndTime());
    this.ignoreAlarmService.add(entity);  // 或 save
    return BaseResult.build().ok();
}
```

**优先级**：🟡 **中** — 不影响 dedup/ignore 主流程，但前端 UI 完全不可用。
