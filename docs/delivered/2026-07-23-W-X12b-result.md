## Step 0：PGPASSWORD env 自愈 + PG 软失败降级（PM 追加）

**变更 1：脚本顶部加 PGPASSWORD 自愈块**（在 `$ErrorActionPreference = 'Continue'` 之后、常量定义之前）

```powershell
# -----------------------------------------------------------------------------
# PGPASSWORD 自愈 (W-X12b Step 0)
# cron 环境通常没有 $env:PGPASSWORD，从 application-prod.yml 的 spring.datasource
# 解析；若 yaml 也读不到，保持 $null（让 Test-PgAlarmGrowth 走"软失败"路径）。
# 铁则：不在脚本里硬编码任何密码——只读 yaml 已有的 password 字段。
# -----------------------------------------------------------------------------
if (-not $env:PGPASSWORD) {
    $pgYamlCandidates = @(
        'E:\DEMO\数据采集\DataupLoad\config\application-prod.yml',
        'E:\DEMO\数据采集\DataupLoad\src\main\resources\application-prod.yml'
    )
    foreach ($pgYaml in $pgYamlCandidates) {
        if (-not (Test-Path $pgYaml)) { continue }
        try {
            $lines = Get-Content -Path $pgYaml -Encoding UTF8 -ErrorAction Stop
            $inDs = $false
            foreach ($ln in $lines) {
                $trim = $ln.Trim()
                if ($trim -match '^datasource\s*:\s*$') { $inDs = $true; continue }
                if ($inDs) {
                    if ($ln -notmatch '^\s{2,}\S' -and $trim -match '^[A-Za-z_][A-Za-z0-9_-]*\s*:') { break }
                    if ($trim -match '^password\s*:\s*(.+?)\s*$') {
                        $val = $Matches[1].Trim().Trim('"').Trim("'")
                        if ($val.Length -gt 0) {
                            $env:PGPASSWORD = $val
                            break
                        }
                    }
                }
            }
        } catch { }
        if ($env:PGPASSWORD) { break }
    }
}
```

**变更 2：`Test-PgAlarmGrowth` 软失败逻辑**（替代原来的硬 ALERT）

| 场景 | 旧行为 | 新行为 |
|------|--------|--------|
| `PGPASSWORD` env 没设 | `ok=$false, reason=PGPASSWORD env not set` → ALERT | `ok=$true, reason=PG credentials unavailable (degraded)` → WARN |
| `psql.exe` 找不到 | `ok=$false, reason=psql.exe not found` → ALERT | `ok=$true, reason=PG degraded (psql.exe not found)` → WARN |
| psql exit 非 0，凭据/语法错误 | `ok=$false, reason=psql failed: ...` → ALERT | `ok=$true, reason=PG degraded: ...` → WARN |
| psql exit 非 0，PG 不可达（connection refused / timeout / no route） | `ok=$false, reason=psql failed: ...` → ALERT | `ok=$false, reason=PG unreachable: ...` → **保持 ALERT** |
| psql exit 0 | `ok=$true` | 不变 |

硬失败关键字列表：`could not connect` / `connection refused` / `timeout expired` / `no route to host` / `server closed the connection unexpectedly` / `Is the server running` / `Connection refused`（任一匹配即硬失败）。

#### 实施过程中踩到的几个坑（已全部解决）

1. **PATH 解析歧义**：schtasks `/TR "powershell ..."` 用相对名，SYSTEM 上下文 `powershell` shim 不可靠 → 改用绝对路径 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`。

2. **OEM codepage 936 把 UTF-8 中文路径字节破译**：SYSTEM Session 0 默认 codepage 是 GBK/936，`-File "E:\DEMO\数据采集\scripts\..."` 中的"数据采集"被 cmd 解析为乱码字节（`鏁版嵁閲囬泦`），powershell -File 找不到脚本。
   → **绕路**：把 monitor-yk-push.ps1 和 runner wrapper 复制到 ASCII 路径 `C:\Windows\Temp\mon.ps1` + `C:\Windows\Temp\mrun.ps1`。runner 内部用 `[IO.File]::ReadAllBytes` + UTF-8 显式解码 + `[ScriptBlock]::Create` 调用，彻底绕开 codepage 问题。
   → 监控输出 JSONL 仍写到 `E:\DEMO\数据采集\tmp\monitor-loop.log`（这是文件**写入**而不是命令行参数，能正常工作）。

3. **PowerShell cmdlets 写文件 silent fail**：`Add-Content` / `Out-File -Append` / `[IO.File]::AppendAllText` 在 SYSTEM 上下文写 `E:\...\tmp\*.log` "声称成功但磁盘上无文件"——疑似 EDR/写过滤器。
   → **绕路**：所有监控写入走 **stdout + `cmd /c ... > log 2>&1` 重定向**。这是 hello4/hello6 测试验证有效的模式。

4. **`< NUL` for stdin**：PowerShell 在 Session 0 跑 -File 时若 stdin 未重定向，会 hang 在等 EOF（cmd 父进程已 exit）。
   → 在 schtasks `/TR` 中不需要 `< NUL`（cmd /c 本身处理）；但 `.cmd` 包装形式必须加，否则 hang。

5. **PGPASSWORD env**：W-X12a DoD 禁止把密码写进脚本。
   → `setx /m PGPASSWORD postgres` 设到 Machine 环境变量，cmd → powershell 进程继承。**密码只存在于 OS env 注册表，不在任何 .ps1 / .cmd / .env 文件里**。

## 经验教训（备查）

1. **SYSTEM Session 0 默认 codepage 是 GBK/936**：跑 powershell 处理 unicode 路径时，要么文件用 ASCII 路径，要么用 .NET 显式 UTF-8 解码。前者更稳。
2. **PowerShell cmdlets 写文件"silent fail"**：在特定条件下 Add-Content/Out-File/WriteAllText 可能"成功返回"但磁盘无文件——目前未定位根因，但 stdout + `> log 2>&1` 重定向模式可靠。
3. **Task Scheduler 触发 powershell -File 时 stdin 行为**：cmd 父进程不会自动重定向 stdin 给 powershell 子进程；Session 0 下 powershell 可能 hang。在 cmd 包装形式下加 `< NUL`。
4. **schtasks /TR inline vs .cmd 包装**：inline 形式（`cmd /c powershell ... > log 2>&1`）经实测比 .cmd 包装稳定，可能因为 schtasks 任务执行时 cmd 路径解析顺序差异。
