## Step 1：监控 4 项指标函数（10 min 目标）

✅ 完成。脚本 `scripts/monitor-yk-push.ps1`（约 12.5 KB）包含 4 个独立函数 + 1 个主函数：

| 函数 | 职责 | 关键实现 |
|---|---|---|
| `Test-YkEnable` | 读 `application-prod.yml` 中 yk.enable | 状态机解析，先匹配 `yk:` 段，再匹配 `enable: true\|false`，再用"非 yk 子段缩进"判断退出。**只读** |
| `Test-YkTicketCall` | 扫 log 目录最近 1 min | 流式 `[System.IO.File]::OpenText`，grep `ticket success` / `updateTicket:8[0-9] success`，只统计 `LastWriteTime >= now-1min` 的文件 |
| `Test-PgAlarmGrowth` | 对比 alarm_record 行数 5 min 内增长 | `psql.exe`（PATH 优先 → `C:\Program Files\PostgreSQL\14\bin\psql.exe` 兜底）+ `$env:PGPASSWORD`（**铁则：禁硬编码**）。state 文件存 `%TEMP%\monitor-yk-push-state.json`，保留 30 min 样本，找 4-6 min 容忍窗内基线 |
| `Test-HikJavaAlive` | hik-java.exe 进程 + 端口 80 | `Get-CimInstance Win32_Process -Filter "Name='hik-java.exe'"`（**铁则 38：禁 `Get-Process -Name java`，会漏 hik-java.exe**），PID 比对 `Get-NetTCPConnection -LocalPort 80 -State Listen` |
| `Invoke-Monitor` | 调 4 项 + 输出 JSON | 任一异常 → `status: ALERT` + `alert_reason`；全 OK → `status: OK` |

### 调试中暴露并修复的 2 个 bug

1. **yk.enable 解析提前 break**：原写法把"退出 yk 段"判断放在 `enable` 匹配之前，导致 `enable: false` 行先触发"是 key" 提前 break。修法：把 enable 匹配前置 + 用"非 2+ 空格缩进且是顶层 key"判断退出。
2. **`& psql.exe` 走 PowerShell cmdlet 解析失败**：PowerShell 把 psql.exe 当 cmdlet 查找，没在 PATH 时报 not recognized。修法：探测到 PATH 或 `C:\Program Files\PostgreSQL\1[3-6]\bin\psql.exe`，用绝对路径调用。
