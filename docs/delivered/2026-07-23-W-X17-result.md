## T3: ignore 过期清理 (IgnoreExpireTask)

### 结论：**❌ FAIL（产线现网已坏了 4 小时）**

**代码核查**（`IgnoreExpireTask.java` 第 50–56 行）:
```java
LambdaQueryWrapper<IgnoreAlarm> qw = Wrappers.<IgnoreAlarm>lambdaQuery()
    .lt(IgnoreAlarm::getIgnoreTime, LocalDateTime.now());  // ← BUG: getIgnoreTime 字段在 DB 不存在
int count = (int) ignoreAlarmService.count(qw);            // ← 第一次 SQL 报错
ignoreAlarmService.removeExpire();                          // ← 第二次 SQL 也错（见下）
```

**两个 BUG**:

### BUG #1: `IgnoreAlarm.ignoreTime` 字段未映射到任何 DB 列

- `IgnoreAlarm.java` 第 22 行有 `private LocalDateTime ignoreTime;`
- 但**没有 `@TableField` 注解**（对照 `endTime` 字段有 `@TableField("end_time")`）
- DB `ignore_alarm` 表里**没有** `ignore_time` 列（只有 `start_time` / `end_time` 两个 varchar(19) 列）

→ MP 生成的 SQL 是 `SELECT COUNT(*) FROM ignore_alarm WHERE ignore_time < ?` → PG 报 `字段 "ignore_time" 不存在`

### BUG #2: `IgnoreAlarmServiceImpl.removeExpire()` 跨类型比较

- `removeExpire()` 第 49–51 行：`lt(IgnoreAlarm::getEndTime, LocalDateTime.now())`
- `end_time` 列类型是 **`character varying(19)`**（不是 timestamp）
- MP 生成 SQL `WHERE end_time < ?`，参数是 LocalDateTime→timestamp
- → PG 报 `操作符不存在: character varying < timestamp with time zone`
