# 001. 采集方案选择：A2零侵入直读海康PG为主链路

日期：2026-07-06
状态：已接受

## 背景

青州工厂工控机已部署海康视觉平台（hik-java.exe + PostgreSQL + SourceManager看门狗+加密狗），需要从海康系统获取视觉检测的缺陷/报警/结果数据，上传到英科MES系统。三个备选方案：
- A1：旁路监听/代理拦截海康到MES的上传流量
- A2：零侵入直读海康PG `intco` 库
- A3：网卡抓包解析
- DUAL：A1+A2双轨

现场约束：
- 海康SourceManager看门狗5秒巡检，对进程/端口/配置变化极敏感，误触发会导致停线
- 加密狗不可碰，任何代理/中间人可能被看门狗判定为异常
- C盘仅剩14.5GB，不允许安装重服务
- 海康已占用大量端口（80/443/5432/3306/6379/7000段/40000-42020段/50000-50020段等）

## 选项

| 方案 | 优点 | 缺点 |
|---|---|---|
| A1 代理拦截 | 可获取完整上传事件、可审计 | 需要改海康配置或起代理，看门狗风险极高；现场初期误判为主方案，现场探查后否决 |
| A2 PG直读 | 零侵入、不装代理、不改海康配置、只读SELECT即可 | 需要只读账号；需识别表结构；PG连接数需严格控制 |
| A3 网卡抓包 | 完全不碰海康进程 | 解析复杂、丢包风险、只能应急兜底、不适合常驻 |
| DUAL A1+A2 | 双保险、零漏数 | 复杂度翻倍，MVP不适合 |

## 决定

**青州首站MVP采用A2作为唯一主链路**：
- 使用专用只读账号直连127.0.0.1:5432的`intco`库
- 只授予业务表SELECT权限，不给INSERT/UPDATE/DELETE/TRUNCATE
- 增量读取策略优先级：WAL逻辑订阅 → 时间戳轮询 → ID+时间戳双游标
- 严禁在海康库建表/建触发器/改schema/跑维护语句
- A1仅预留接口不实装；A3仅作为应急兜底不默认启用；DUAL代码预留抽象不开启

## 后果

1. 对海康进程零打扰，满足"不影响生产"最高优先级
2. 依赖海康配合开通PG只读账号（当前P2等待，MVP不阻塞，先做MES上传+Mock）
3. 后续其他车间复制时，必须每个车间重新探查PG版本/表结构/权限，不能假设与青州一致
4. 连接池、轮询频率必须保守设置（CPU<20%预算、小连接池、指数退避）
