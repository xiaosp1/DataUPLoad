## 完整根因（4 层叠加）

### Layer 1: 老 PSM 前端 Login.vue 路由不挂载
- 现代浏览器（Chrome 80+ / Edge）对老旧 Vue 2 插件兼容性差，Login.vue 路由挂载失败
- 点击登录按钮，JS 报错吞掉，请求没发出
- **症状**：点击无任何反应

### Layer 2: framework-starter 静态资源映射不全
- `WebConfigure` 只映射：`/index.html`、`/js/**`、`/assets/**`、`/vite.svg`、`/version.json`、`/web/help/**`、`/public/**`、`/log/**`
- **不映射**：`/login.html`、`/legacy.html`、`/browser.js`、`/AI.png` 等独立文件
- `hik-res.res-map`（`config/application-prod.yml`）的 PSM 沿用配置**静默失效**——`/data/**` 也 404，但项目暂时不依赖它
- **症状**：写独立 login.html → 浏览器 GET 500

### Layer 3: PSM 老 SPA router 守卫与 sa-token cookie 名不匹配
- 路由表（`index.f19ecd42.js`）：
  - `{path:"/Login", name:"Login"}`
  - `{path:"/", redirect:"/realTime"}`
- 路由守卫：
  ```js
  xe.beforeEach((e,a,r)=>{
    const n = he.get("token");  // ← PSM 老 SPA 用 js-cookie 读 document.cookie "token"
    if (e.name === "Screen") r();
    else if (!n && e.name !== "Login") r({path:"/Login"});  // ← 没 token → 踢回 Login
    else if (n && e.name === "Login") r({path:"/"});
    ...
  });
  ```
- `he` 是 vendor-legacy 里的 **js-cookie** 实例（不是 localStorage）
- **关键不匹配**：
  - PSM 老 SPA 期望 cookie 名 = `token`
  - 后端 sa-token 框架设的 cookie 名 = `satoken`
- **症状**：登录成功后 satoken cookie 浏览器自动带，但 router 守卫读 `token` cookie 不存在 → 立即 push 到 `/Login` → 「一闪而过」

### Layer 4: changeUser store action 不存 token
- 登录成功（`POST /web/auth/login` 200）→ 调 `U.changeUser(...)`（Vuex action）
- `changeUser` 实现（`index-legacy.0208e821.js:68959`）：
  ```js
  changeUser:function(e) {
    this.username = e.username; this.role = e.role; this.permission = e.permission;
    sessionStorage.setItem("user", e.username);
    sessionStorage.setItem("role", e.role);
    sessionStorage.setItem("permission", e.permission);
    // ← 不存 token 任何地方！
  }
  ```
- **整个 PSM 老 SPA 没有任何代码把 satoken 复制成 cookie `token`**——这是个**设计 bug**

## 解决方案：单文件智能 gate-routing

**`web/index.html` 一文件搞定**：
- 同一文件根据登录态切换两阶段：
  - **登录前**：纯 HTML/CSS 登录表单（SHA256 + fetch `/web/auth/login`）
  - **登录后**：动态注入 PSM 老 SPA 的 `<script>`/`<link>` 标签
- **关键修复**：
  1. 登录成功 → 调 `syncTokenToLocalStorage()` 把 satoken 值复制成 cookie `token`：
     ```js
     document.cookie = "token=" + encodeURIComponent(satoken) + "; path=/; max-age=2592000; SameSite=Lax";
     // 备份：localStorage.setItem("token", satoken);
     //      sessionStorage.setItem("token", satoken);
     ```
  2. 把 `/browser.js`、`/AI.png` 拷到 `web/js/` 复用 `/js/**` 映射
  3. chunk 内部 `./js/...` 相对路径解析正确（base URL = `/`）

## 风险与已知限制

- **hik-res.res-map 静默失效**：framework-starter 的 `ResourceMapConfig` 没被 Spring 注册。**PSM 沿用的 `/data/**` 映射也是死代码**，但项目用的是 framework-starter 默认 `/data/**` 拦截（hik-security uri-permit），业务暂时无影响
- **新加 PSM 老 SPA 资源到 web/ 需重启**：framework-starter ResourceHandler 实时读文件，但**新加文件需要重启**才生效（注册新路径？）
- **浏览器缓存**：vite 老 bundle 用了 hash 文件名，老浏览器可能缓存，必要时 Ctrl+Shift+R 强刷
- **syncTokenToLocalStorage 是临时补丁**：从根本上应让 PSM 老 SPA 升级成读 satoken cookie，但 PSM 不归我们维护，所以 gate-routing 是当前最佳方案
