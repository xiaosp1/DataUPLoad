# 003. MVP策略：MES上传+Mock先行，海康采集后置

日期：2026-07-06
状态：已接受

## 背景

原计划Day1直接从海康抓取启动，但现场情况：
- MES真实地址和接口规范未最终拿到
- 海康PG只读账号尚未开通
- 5天工期非常紧
- 单人开发

## 选项

| 选项 | 优点 | 缺点 |
|---|---|---|
| 按原计划：海康采集→MES上传一条龙 | 功能完整 | 前置条件不满足会Block；5天内大概率做不完；没有闭环验证 |
| MES上传+Mock先行，海康采集后置 | 可在开发机完全闭环；不依赖现场条件；5天可交付可用的上传链路底座 | Day1-Day5不包含真实海康数据，需要Sprint1补 |

## 决定

**MVP（Sprint 0，5天）交付范围锁定为**：
1. Day1：.NET 8解决方案骨架 + 可观测底座（Serilog+/health） + MES上传接口定义
2. Day2：MES上传核心（HTTP/JWT/SQLite缓存/补传/幂等/重试）
3. Day3：MES Mock服务（本地闭环） + 审计日志
4. Day4：WPF壳 + 诊断页 + 上传看板 + 日志查看器
5. Day5：self-contained打包 + install/uninstall/冒烟测试脚本 + 文档

**明确不做（后置）**：
- 海康PG A2采集器（Sprint1，等账号）
- OPC-UA/EIP（Sprint2，等PLC点表）
- AI诊断（Sprint3）
- Vue大屏（Sprint3）

## 后果

1. 5天可以交付一个"可安装、可启动、可Mock测试上传链路、可看状态、可排错"的底座
2. 即使现场条件不齐（PG账号/MES地址没拿到），交付物仍有独立价值
3. 架构上通过IMesUploader适配器隔离Mock/Real，后续切换真实MES不改业务代码
4. Sprint1接入海康PG时，上传链路/缓存/补传/可观测已经稳定，焦点可集中在采集器本身
