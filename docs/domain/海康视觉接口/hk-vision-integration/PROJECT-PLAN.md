# 项目规划 — HK Vision Integration

> 版本：v0.1（骨架阶段）
> 起止：以本规划建立为 Day 0
> 对接方：海康视觉中控平台 ↔ 英科生产管理系统（dataportal）

---

## 一、目标与范围

### 1.1 业务目标

- 实时将海康视觉检测客户端的异常报警（发生/处理完成两个时点）推送到英科系统；
- 定期从海康拉取小时级缺陷统计数据，用于英科侧报表/分析；
- 基础字典（产线/缺陷/面别）从海康定时同步，避免人工维护。

### 1.2 范围内（MVP）

- HTTP 对接服务（FastAPI）：登录、报警接收、健康检查；
- 主动 HTTP 客户端：海康配置/检测数据查询、英科登录/报警上传；
- 定时调度：字典同步、整点数据拉取；
- 基本可观测性：结构化日志、健康检查、错误告警（日志落盘）；
- 幂等保障：报警重复投递不产生脏数据。

### 1.3 范围外（后续迭代）

- 可视化后台页面；
- 多车间横向扩展的多租户部署；
- 数据持久化到业务库（MVP 阶段只落日志+内存）；
- 告警到企业微信/钉钉等即时通道。

### M2：报警接收链路打通（约 3 人日）

**交付物**
- `HttpxInkeyClient` 真实实现：登录（拿 Ticket）+ 上传报警；
- `/api/dataportal/invoke` 登录接口代理到英科（或本地按配置校验，视部署模式）；
- 报警幂等：以 `WorkShop+Line+Face+AlarmTime+AlarmType` 为幂等键，内存 LRU/文件去重；
- 错误重试：上传失败按指数退避重试 3 次；
- 联调海康测试环境（`http://192.168.32.86:1025`）至少跑通 1 条真实报警。

**验收标准**
- 海康侧使用本服务登录 → 拿到 Ticket → 上传 1 条报警 → 英科库可查到；
- 重复上报相同报警幂等命中，不产生重复数据；
- Ticket 过期时自动重新登录（透明续期）。

| # | 风险 | 影响 | 责任方 | 建议处理 |
|---|---|---|---|---|

## 五、技术决策记录（ADR）

- **语言/框架**：Python 3.11 + FastAPI（轻量、异步友好、自动生成 OpenAPI 文档）。
- **HTTP 客户端**：httpx（原生 async，与 FastAPI 匹配）。
- **配置**：pydantic-settings + `.env`，12-Factor 风格。
- **日志**：loguru（开箱即用，支持按大小/天轮转）。
- **调度**：APScheduler（进程内后台线程，足够当前体量）；若后续多副本部署需改分布式调度。
- **数据持久化**：MVP 阶段内存+日志；M4 根据客户 IT 环境选型 SQLite / Redis / 业务库直连。
- **幂等**：M2 内存 LRU（TTL 24h），M4 切到 Redis/SQLite。
