## 一、整体概述

双方通过 HTTP 接口实现海康视觉中控平台与英科系统之间的数据互通，共涉及 **4 个接口**：

| # | 方向 | 提供方 | 接口 | 方法 | 用途 |
|---|---|---|---|---|---|
| 1 | 海康→英科 | 海康 | 配置查询接口 | GET | 查询产线、缺陷类型、面别等基础配置 |
| 2 | 海康→英科 | 海康 | 视觉检测数据查询接口 | POST | 按时间/产线/缺陷/面别查询次品检测统计数据 |
| 3 | 英科→海康 | 英科 | 登录验证接口 | POST | 获取调用 Ticket |
| 4 | 英科→海康 | 英科 | 报警数据上传接口 | POST | 实时推送异常报警数据（含异常处理后状态） |

**典型调用流程**
1. 海康侧调用英科 **登录接口** 拿到 `Ticket`；
2. 视觉检测产生异常/异常处理完成时，调用英科 **报警上传接口**（Ticket 放 Context）；
3. 英科侧按需调用海康 **配置查询接口** 同步基础字典；
4. 英科侧按需调用海康 **检测数据查询接口** 拉取统计数据。

## 二、海康提供接口

### 接口 1：视觉中控平台配置查询

- **功能**：查询该车间服务下所有产线组、缺陷类型组、面别组
- **方法**：GET
- **URL**：⚠️ 文档中未填，待海康提供

**响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| code | Int | 状态码，200 成功 / 400 失败 |
| results.lineGroup | List\<String\> | 产线组 |
| results.defectGroup | List\<String\> | 缺陷类型组 |
| results.faceGroup | List\<String\> | 面别组 |
| message | String | 异常原因（失败时） |

> ⚠️ 原文示例字段写作 `lindGroup`，疑为 `lineGroup` 笔误，需对齐。

**成功示例**
```json
{
  "code": 200,
  "results": {
    "lineGroup": ["line1A", "line1B", "line2A", "line2B"],
    "defectGroup": ["底面破损", "侧面破损", "二次料"],
    "faceGroup": ["A面", "B面"]
  }
}
```

**失败示例**
```json
{ "code": 400, "results": null, "message": "异常原因" }
```

### 接口 2：视觉检测数据查询

- **功能**：根据条件查询视觉检测出次品的详细数据
- **方法**：POST
- **URL**：⚠️ 待海康提供

**请求参数（Body JSON）**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| time | DateTime | 是 | 时间，格式 `YYYY-MM-dd HH:00:00`（整点） |
| lineGroup | List\<String\> | 否 | 产线，不填默认全部 |
| defectGroup | List\<String\> | 否 | 异常类型，不填默认全部 |
| faceGroup | List\<String\> | 否 | 面别，不填默认全部 |

> ⚠️ 原文字段表写 `linds/defects/faces`，示例写 `lindGroup/defectGroup/faceGroup`，命名不一致，需对齐。

**请求体示例**
```json
{
  "time": "2024-08-13 14:00:00",
  "lineGroup": ["line1A", "line1B", "line2A", "line2B"],
  "defectGroup": ["底面破损", "侧面破损", "二次料"],
  "faceGroup": ["A面", "B面"]
}
```

**响应字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| code | Int | 状态码 |
| success | Boolean | ⚠️ 示例中有、表格未列，需确认 |
| data.defects | List\<Object\> | 缺陷统计列表 |
| data.defects[].time | DateTime | 统计时间 |
| data.defects[].line | String | 产线 |
| data.defects[].defect | String | 缺陷类型 |
| data.defects[].face | String | 面别 |
| data.defects[].detectionCount | int | 检测异常数量 |
| data.removeCounts | List\<Object\> | 删除数量列表 |
| data.removeCounts[].line | String | 产线 |
| data.removeCounts[].face | String | 面别 |
| data.removeCounts[].removeCount | int | 删除数量 |
| message | String | 异常原因 |

**成功示例**
```json
{
  "code": 0,
  "success": true,
  "data": {
    "defects": [
      {
        "time": "2024-08-13 14:01:54",
        "line": "line1A",
        "defect": "底面破损",
        "face": "A面",
        "detectionCount": 1
      }
    ],
    "removeCounts": [
      { "line": "line1A", "face": "A面", "removeCount": 1 }
    ]
  }
}
```

**失败示例**
```json
{ "code": 400, "results": null, "message": "异常原因" }
```

> ⚠️ 成功示例外层 `code:0 + success + data`，失败示例外层 `code:400 + results:null`，结构不一致，需统一。

## 三、英科提供接口

> 英科接口统一通过 `POST /api/dataportal/invoke` 入口进入，通过 `ApiType + Method` 区分具体动作；认证信息通过 `Context.Ticket` 传递。

### 接口 3：登录验证接口

- **方法**：POST
- **测试 URL**：`http://192.168.32.86:1025/api/dataportal/invoke`
- **正式 URL**：`http://192.168.80.33:10031/api/dataportal/invoke`

**请求体**
```json
{
  "ApiType": "AuthenticationController",
  "Method": "Login",
  "Parameters": [
    { "Value": "HKSJSB" },
    { "Value": "HKSJSB123" }
  ],
  "Context": {}
}
```
Parameters 顺序固定：第 1 个账号、第 2 个密码。

**返回关键字段**
- `Result.UserCode / UserName`：用户信息
- `Context.Ticket`：后续接口调用凭证
- `Context.InvOrgId`：组织 ID（值为 1）

**返回示例**
```json
{
  "Success": true,
  "Message": null,
  "Result": {
    "UserId": 50001.0,
    "EmployeeId": 60002.0,
    "UserCode": "HKSJSB",
    "UserName": "海康视觉设备[HKSJSB]",
    "InvOrg": 1
  },
  "Context": {
    "Ticket": "7bJQZV6mCvdNBAGqv37bzpK3d5S2s9dfx5XClK4fdYdPXrPssMuSV1bapcvDvw7F6malRs+pwfQfA1Te/EWmTw==",
    "InvOrgId": 1
  }
}
```

> ⚠️ Ticket 有效期未说明，需确认是否需要心跳/重新登录机制。

### 接口 4：报警数据上传接口

- **功能**：视觉检测客户端产生异常报警时调用一次；异常处理完成后再次调用更新结果
- **方法**：POST
- **URL**：同登录接口（`/api/dataportal/invoke`），`ApiType=VisualInspectionController`，`Method=HandleVisualInspectionAlarm`
- **特性**：
  1. 支持批量传输（`Value` 为数组）；
  2. 海康侧不做去重，英科侧需考虑幂等；
  3. 异常发生、异常处理完成 **都** 要调一次。

**请求骨架**
```json
{
  "ApiType": "VisualInspectionController",
  "Method": "HandleVisualInspectionAlarm",
  "Parameters": [
    { "Value": [ /* 报警对象数组 */ ] }
  ],
  "Context": {
    "Ticket": "<登录返回的 Ticket>",
    "InvOrgId": 1
  }
}
```

**报警对象字段（Value 数组元素）**

| 字段 | 类型 | 说明 |
|---|---|---|
| WorkShop | String | 车间代码（固定枚举值，见第四节） |
| Line | String | 产线 |
| Face | String | 面别 |
| AlarmTime | String | 报警时间（示例格式 ISO：`2024-08-30T14:30:00`） |
| AlarmType | String | 报警类型 |
| AlarmLevel | String | 报警等级 |
| AlarmDetails | String | 报警内容 |
| AlarmResult | String | 处理结果（如 "已处理"；未处理时的取值待确认） |
| AlarmCount | Number | 报警次数 |

**请求示例**
```json
{
  "ApiType": "VisualInspectionController",
  "Parameters": [
    {
      "Value": [
        {
          "WorkShop": "TEST",
          "Line": "Line A",
          "Face": "Front",
          "AlarmTime": "2024-08-30T14:30:00",
          "AlarmType": "Temperature Alert",
          "AlarmLevel": "High",
          "AlarmDetails": "Temperature exceeded threshold",
          "AlarmResult": "已处理",
          "AlarmCount": 1
        }
      ]
    }
  ],
  "Method": "HandleVisualInspectionAlarm",
  "Context": {
    "Ticket": "7bJQZV6mCvdNBAGqv37bzpK3d5S2s9dfx5XClK4fdYdPXrPssMuSV1bapcvDvw7F6malRs+pwfQfA1Te/EWmTw==",
    "InvOrgId": 1
  }
}
```

**响应判定**
- 外层 `Success` 恒为 `true`（即使业务失败），实际业务结果看 `Result.code`：
  - `Result.code = 200` → 成功
  - `Result.code = 400` → 失败，`Result.message` 为错误原因

**失败示例**
```json
{
  "Success": true,
  "Result": {
    "code": 400,
    "message": "处理报警时出错: Object reference not set to an instance of an object."
  }
}
```

## 五、文档待确认问题清单（落地前需双方对齐）

1. **URL 缺失**：接口 1、接口 2、接口 4 的完整路径文档为空。
2. **字段命名不一致**：
   - 多处 `lindGroup` / `linds` 疑为 `lineGroup` / `lines` 笔误；
   - 接口 2 请求表字段名（`linds/defects/faces`）与示例（`*Group`）不一致。
3. **响应结构不统一**：接口 2 成功用 `success + data.defects`，失败用 `results:null`，建议统一外层封装。
4. **接口 2 时间语义**：参数 `time` 传整点，但示例明细时间精确到秒，需明确是"查该小时内全部数据"还是"查该时点数据"。
5. **AlarmResult 取值枚举**：未处理/已处理/误报/待复核 等状态值没有标准枚举。
6. **时间格式**：英科接口示例用 ISO `T` 分隔，海康接口示例用空格分隔，建议统一（推荐 ISO 8601）。
7. **海康接口鉴权**：海康两个接口是否需要鉴权（Token / IP 白名单）未说明。
8. **removeCounts 语义**："删除数量"是次品被剔除数量还是数据删除次数，需业务澄清。
9. **报警幂等策略**：海康不做去重，英科侧需明确幂等键（建议 `WorkShop + Line + Face + AlarmTime + AlarmType`）。
10. **接口编号重复**：原文两个"接口二"，本整理稿已重编为 1–4，双方文档建议同步更新。
11. **Ticket 有效期与刷新**：登录返回的 Ticket 过期时间、续签机制未说明。
12. **批量上限**：报警上传 `Value` 数组最大条数未约定。
13. **网络连通**：测试/正式环境的网络白名单、端口开放需提前打通。
