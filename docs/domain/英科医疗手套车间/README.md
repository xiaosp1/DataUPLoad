## 🔢 命名约定（★ 关键）

### 线的方位（南/北）

```
                ┌─── 北 ───┐
   ─────────────────────────────────
   ║  ┌──────┐         ┌──────┐  ║
   ║  │ A1 排 │         │ B1 排 │  ║    ← 每条产线 4 排手模
   ║  └──────┘         └──────┘  ║
   ║  ┌──────┐         ┌──────┐  ║
   ║  │ A2 排 │         │ B2 排 │  ║
   ║  └──────┘         └──────┘  ║
   ─────────────────────────────────
                └─── 南 ───┘
```

- **A 面**：北边两排手模
  - **A1 排**：靠北那一排
  - **A2 排**：靠南那一排（但仍属 A 面）
- **B 面**：南边两排手模
  - **B1 排**：靠南那一排
  - **B2 排**：靠北那一排（但仍属 B 面）

⚠️ **命名容易混淆**——A/B 是"南北分组"（面），A1/A2/B1/B2 是"排号"，**不是简单地从北到南递增**。

### 命名在数据库里的对应

| 现场说法 | PSM DB 字段 | PSM DTO 字段 | 说明 |
|---|---|---|---|
| 产线编号 L01 ~ L10 | `line.line_no` | `DetectDataUploadDTO.lineNo` / `AlarmDTO.lineNo` | 一条产线一个唯一编号 |
| 面编号 A / B | `line.face_no` | `DetectDataUploadDTO.faceNo` / `AlarmDTO.faceNo` | 每条产线对应 2 个面（一张产线有 2 条 face_no 记录） |
| 手模排号 A1/A2/B1/B2 | （暂未直接入 DB） | （暂未直接入 DTO） | ⚠️ 命名约定，PSM/EdgeHost 当前**没有显式存储**，只在视觉软件端用 |

## 📊 PSM 在现场的作用（业务级）

老板 15:09 现场描述（白话版整理）：

### 1. 接收（★ 被动）

PSM 接收**视觉检测软件**推过来的两类数据：
- **缺陷数据**：每个相机检测到手套有缺陷时，POST 一条缺陷记录到 PSM 的 `/client/data/detect`
- **报警数据**：相机异常、产线停线等报警，POST 到 PSM 的 `/client/data/alarm`

### 2. 解析 + 存库

PSM 收到后：
- 解析 JSON → 校验 → 写入 PostgreSQL 数据库
- 缺陷数据 → `defect_record` 表
- 报警数据 → `alarm_record` 表

### 3. 暴露给 MES（★ MES 主动拉）

MES 系统主动**调 PSM 的接口**来**拉缺陷数据**：
- 调 `/client/yk/defect-record` 按时间范围 + 产线 + 缺陷类型查询
- 调 `/client/yk/line-defect` 拉产线+缺陷字典

### 4. 主动推报警给 MES（★ PSM 主动推）

**报警数据**跟缺陷数据不同——**不是 MES 拉，是 PSM 主动推**：
- PSM 收到报警 → 触发推送逻辑 → POST 给 MES 系统

⚠️ **PM 待确认**：PSM 主动推 MES 走的是什么协议？HTTP POST？还是 WebSocket？还是别的？

## 🎯 EdgeHost 在现场的作用（推断 + 待确认）

按 ADR-004 设计，EdgeHost 应该在现场做"PSM ↔ MES"对接的**中间层**：
