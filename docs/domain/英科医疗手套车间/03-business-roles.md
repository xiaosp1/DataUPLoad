# 03. 角色职责边界

> 本文档定义现场 4 个角色的职责边界：**视觉软件 / PSM / EdgeHost / MES**。
> 谁干什么、不干什么、谁依赖谁。

---

## 👥 4 个角色

### 1. 视觉检测软件（运行在现场工控机 / 相机控制盒）

**职责**：
- 控制 120 个视觉相机采集图像
- 图像处理（识别手套缺陷类型）
- 决定当前手套是"良品"还是"次品"
- 检测到次品 → **POST /client/data/detect 推 PSM**
- 检测到设备异常（相机掉线 / 光源异常）→ **POST /client/data/alarm 推 PSM**
- 定时上报心跳 → **POST /client/data/status**

**不负责**：
- ❌ 不直接对接 MES（必须经过 PSM）
- ❌ 不做数据汇总 / 统计
- ❌ 不持久化（只管推，推完不管）

**PM 待确认**：
- 软件品牌（海康 VisionMaster / 自研 / 第三方？）
- 部署位置（每台工控机一个？容器化？）
- 是否含"剔除机联动"逻辑（次品自动剔除？）

### 2. PSM（海康大屏中间件，Spring Boot 3）

**职责**：
- 接收视觉软件推过来的**缺陷 / 报警 / 状态**数据
- 解析 + 校验 + 写入 PostgreSQL
- 提供**字典 / 配方**查询接口给 MES
- 提供**缺陷记录**查询接口给 MES（拉）
- **主动推送报警**给 MES（推，协议待定）
- 大屏展示（Web 界面，给现场操作员看实时数据）

**不负责**：
- ❌ 不直接控制相机（相机由视觉软件控制）
- ❌ 不做 MES 业务逻辑（PSM 只暴露数据，不做生产管理）
- ❌ 不持久化图片（`defect_record.img_list` 是路径字符串，图片在别处存）

**对接**：
- 上游：120 个视觉软件客户端（HTTP POST）
- 下游：MES 系统（HTTP REST + 待定的推送协议）
- 外部：英科 `192.168.80.33:10031` 系统（yk 模块拉数据用）

### 3. EdgeHost（我们要做的 / 已存在）

**职责（按 ADR-004 设计）**：
- 接收 MES 的"拉缺陷"请求，转发到 PSM（或本地缓存返回）
- 接收 PSM 推送的报警，转发给 MES（或本地处理）
- 做数据统计 / 聚合 / 缓存
- 做数据镜像（拉 PSM 数据到本地 SQLite，方便 MES 高频查询）

**不负责**：
- ❌ 不接收视觉软件的推数据（这是 PSM 的活）
- ❌ 不做相机控制
- ❌ 不做大屏展示（这是 PSM 的活）

**对接**：
- 上游：PSM REST API + （未来）PSM 推送
- 下游：MES REST API
- 本地：SQLite 数据库（intco.db）

### 4. MES 系统（英科自己的）

**职责**：
- 生产排程（每个班次生产哪种手套多少只）
- 质量追溯（每只手套的缺陷历史）
- 报警通知 / 处理
- 报表生成
- 上下游业务系统对接

**对接 PSM 方式**：
- **主动拉**：MES 调 PSM `/client/yk/*` 和 `/client/plan` 拉数据
- **被动收**：MES 接收 PSM 推送的报警

**PM 待确认**：
- MES 是什么软件（英科自研 / 第三方 / 西门子 / 宝信？）
- MES 调 PSM 的频率
- MES 期望 PSM 推报警的协议 + 端点
- MES 期望 EdgeHost 提供什么接口（如果有）

## 🎯 关键边界约定（★ EdgeHost 设计要遵守）

### EdgeHost **不能做**的事

1. ❌ 取代 PSM 接收视觉软件的数据（PSM 是唯一接收方）
2. ❌ 改 PSM 的配置 / 数据库
3. ❌ 在 EdgeHost 上做大屏展示（PSM 已经有）
4. ❌ 直接控制视觉相机

### EdgeHost **能做**的事

1. ✅ 拉 PSM 的数据做本地镜像（SQLite）
2. ✅ 翻译 PSM 的数据格式给 MES（字段名映射、单位换算等）
3. ✅ 聚合统计（日报 / 班报 / 缺陷率）
4. ✅ 缓存 PSM 的字典 / 配方（高频查询优化）
5. ✅ 中转 PSM 推送给 MES 的报警（如果决定走中转方案）
6. ✅ 做健康检查 / 异常告警（如果 PSM/MES 任一宕了，EdgeHost 发钉钉/微信告警）

### 视觉软件 / PSM / MES **都依赖 EdgeHost 提供**的事

1. 暂无（EdgeHost 是可选层，不是主链路）

## ⚠️ EdgeHost 的"该不该做"判断原则

老板经常问"这个功能 EdgeHost 该不该做？"——按这个判断表：

| 问题 | EdgeHost 该做吗 | 理由 |
|---|---|---|
| 视觉相机数据汇总 | ❌ | PSM 已经做了 |
| 大屏可视化 | ❌ | PSM 已经做了 |
| MES 拉缺陷 | ✅ | 翻译 + 缓存 |
| 报警推送 | 🟡 看方案（见 02-data-flow.md） | 等老板拍 |
| 数据统计 | ✅ | PSM 不暴露 stats |
| 设备健康监控 | ✅ | PSM 有 status_record 但没监控 |
| 班次切换 / 配方分发 | ❌ | 工程师通过 PSM web 后台操作 |
| 视觉软件部署 / 升级 | ❌ | 那是运维 + 视觉软件厂商的事 |
| MES 与 PSM 鉴权中转 | 🟡 看是否需要 | PSM 的 /client/* 公开免登录 |
| EdgeHost 自身健康监控 | ✅ | 用 OpenClaw / 钉钉 |
